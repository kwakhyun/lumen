# 검색 노출과 사업 성과 검증 기능 — 2026-10-22

이번 변경은 API 답변에서 계산한 지표의 오류를 바로잡고, 실제 AI 검색 화면의 관측과 콘텐츠 변경 전후의 방문, 전환, 매출을 별도로 비교할 수 있도록 만든다. **노출이나 매출이 실제로 증가했다는 결과 보고서가 아니다.** 실제 효과를 판단하려면 계획한 기간의 검색 근거와 사업 집계를 앞으로 기록해야 한다.

이 문서를 작성한 시점의 통합 테스트는 **204개 통과**, TypeScript 검사는 통과했다. 로컬 브라우저 검증은 진행 중이며, 이 문서는 배포 성공이나 운영 데이터의 효과 검증 완료를 확인하는 증거로 사용하지 않는다. 운영 7일 검증도 아직 완료로 판정하지 않는다.

## 측정 환경과 지표

무료 Gemini 수집은 웹 검색을 사용하지 않는 API 일반 응답이다. 브랜드를 어떤 문맥에서 설명하는지는 알 수 있지만 소비자용 Gemini, ChatGPT 또는 Perplexity 검색 화면의 노출을 측정한 결과는 아니다. 무료 Gemini의 답변 변화만으로 웹 콘텐츠 수정의 효과를 판단할 수 없다.

기존 대시보드의 지표 버전은 `lumen-metrics-v2`다. 실제 응답과 합성 샘플을 분리하고, 동일한 답변 ID와 브랜드 도메인을 중복 집계하지 않는다. 요약은 선택한 기간 안에서 가장 최근에 종료된 수집을 사용한다. 최신 수집이 실패했으면 이전 성공 수집으로 대체하지 않는다. 추이 차트에는 기간 안에 저장된 완료 답변이 남는다.

| 지표 | 분자 / 분모 | 제외 및 해석 기준 |
| --- | --- | --- |
| 브랜드 언급률 | 브랜드를 언급한 완료 답변 / 전체 완료 답변 | 답변마다 브랜드당 최대 1회. 실패와 진행 중 답변 제외. |
| 브랜드 인용률 | 자사 도메인을 인용한 답변 / 검색 인용을 제공하는 완료 답변 | 알려진 검색 수집 모델인 `gpt-4.1-mini`, `perplexity/sonar`만 실제 인용 측정 대상. 무료 Gemini와 지원 여부가 불명확한 모델 제외. |
| 언급 점유율 | 자사 언급 / 자사와 등록된 경쟁사의 전체 언급 | 시장 전체 점유율이 아니다. 경쟁사 목록을 바꾸면 과거 집계도 달라진다. |
| 질문 수집률 | 완료 답변이 있는 활성 질문 / 전체 활성 질문 | 수집 진행 정도다. 브랜드 노출률이 아니다. |
| 브랜드 언급 질문 비율 | 브랜드를 언급한 완료 답변이 하나 이상 있는 활성 질문 / 전체 활성 질문 | 같은 질문은 한 번만 센다. 미수집 질문도 분모에 남는다. |
| 평균 등장 순서 | 브랜드가 언급된 답변에서 추적 브랜드 중 처음 등장한 순서의 평균 | 실제 검색 순위와 다르다. |

인용률은 측정 가능한 답변이 없으면 `null`과 ‘측정 불가’를 사용한다. 측정 대상은 있지만 자사 인용이 없으면 `0%`다. Gemini 8개와 검색 인용 제공 답변 2개 중 1개에 자사 인용이 있으면 인용률은 **1/2 = 50%**다. Gemini를 분모에 넣어 10%로 낮추지 않는다. 화면에는 분자와 분모, 실패 수와 인용 측정 제외 수를 함께 표시한다.

API 인용은 제공자의 인용 메타데이터와 실제 URL의 호스트가 일치해야 한다. 본문에 URL이 적혀 있다는 이유만으로 인용으로 세지 않는다. 출처 목록도 같은 기준을 사용한다. `brand.com.attacker.test`는 `brand.com`의 인용으로 인정하지 않는다. 합성 샘플의 인용은 합성 데이터 안에서만 계산한다.

## 실제 검색 근거와 콘텐츠 변경 전후 비교

새 ‘검색과 매출 검증’ 기능의 지표 버전은 `lumen-impact-v1`이다. 별도의 AI 호출이나 자동 브라우징을 실행하지 않으며, 사용자가 실제 검색 화면과 보고서에서 확인한 자료를 직접 기록한다. 답변의 진위, 검색 실행 여부, 보고서의 정확성을 Lumen이 독립적으로 검증했다고 표시하지 않는다.

계획에 저장하는 항목은 가설, 콘텐츠 변경 내용과 버전, 적용 시각, 전후 기간, 검색 서비스와 모델, 언어, 국가, 기기, 개인화 조건, 질문, 대상 페이지, 반복 횟수, 전환 정의와 매출 귀속 기준이다. 개선 대상과 그대로 둘 비교 대상에 질문을 하나 이상 배정하며 같은 페이지를 양쪽에 넣을 수 없다. 질문은 총 2~20개, 질문별 반복은 각 기간 1~3회다.

전후 기간은 UTC 날짜 기준으로 시작일과 종료일을 포함해 각각 1~90일이며, 길이가 같고 겹치지 않아야 한다. 콘텐츠 적용 시각은 변경 전 기간 종료 다음 날 00:00 UTC부터 변경 후 기간 시작 00:00 UTC 사이여야 한다. 입력 화면의 시각은 한국 시간으로 받고 UTC로 변환한다. 잘못된 시간대, 유효하지 않은 날짜와 미래 관측을 거부한다. 관측 시작 이후에 등록한 계획은 사후 등록으로 표시한다. 계획에 시각을 입력하는 것은 콘텐츠의 실제 게시나 검색 색인 반영을 자동 확인하는 행위가 아니다.

검색 관측에서는 다음을 구분한다.

- 정상 AI 답변, AI 답변 미표시, 확인 실패.
- 사용자가 웹 검색 사용을 확인했는지 여부.
- 브랜드 언급 있음, 없음, 판단 보류.
- 원래 인용 목록 전체를 검토했는지 여부.
- `original_citation`: 원래 AI 답변에 표시된 인용.
- `followup_search`: 나중에 따로 찾아본 검색 결과. 참고 자료로 보관하지만 원래 답변의 인용률에는 포함하지 않는다.

관측 시각, 답변 발췌, 선택적인 근거 URL과 메모를 저장한다. 일반 대화나 검색 사용 여부를 확인하지 못한 응답은 검색 노출 비율에서 제외한다. 원래 인용을 등록하려면 검색 사용 여부를 확인해야 한다. 개인정보, 기밀, 인증 정보가 들어간 URL과 개별 고객 정보는 입력 대상이 아니다.

전후 비교의 분모는 **같은 질문 ID와 반복 번호에서 양쪽 모두 측정 가능한 답변이 있는 쌍**이다. 언급률은 두 답변 모두 검색 확인과 언급 판정이 끝나야 한다. 인용률은 두 답변 모두 검색 확인과 원래 인용 목록 검토가 끝나야 한다. 따라서 언급률과 인용률의 분모가 서로 다를 수 있다. 오류, AI 답변 미표시, 검색 미확인, 판단 보류, 미관측은 해당 비율에서 제외하고 별도의 누락 표에 보여준다. 누락 사유는 서로 겹칠 수 있다.

분모가 0이면 측정 불가다. 실제 미언급 또는 미인용으로 확인된 답변은 0에 포함된다. 반복 관측 수는 독립적인 고객 수가 아니며, 이 비율을 모든 실제 이용자의 노출 확률로 확대해서 해석하지 않는다.

## 방문, 전환과 매출

개선 대상과 비교 대상의 변경 전후, 총 4개 구간을 같은 기간과 집계 기준으로 기록한다. 자동 GA4 가져오기를 추가로 실행하지 않는다. GA4 보고서, 판매 시스템 보고서 또는 직접 집계한 결과를 수동으로 옮기는 기능이다.

각 기록에는 출처 종류, 안정적인 출처 식별자 `sourceId`, 개별 보고서와 필터를 설명하는 `sourceRef`, UTC 집계 여부와 계획의 집계 정의를 지켰다는 사용자 확인이 필요하다. 네 구간의 **출처 종류와 `sourceId`가 모두 같아야** 비교값을 계산한다. `sourceRef`는 기간별 보고서와 필터의 근거를 남기는 필드이며 문자열이 같아야 하는 필드는 아니다. 출처 식별자 일치는 사용자의 선언을 검사한 결과이지, 원본 GA4 속성이나 보고서를 인증한 결과가 아니다.

보고서 시간대는 `UTC`, 집계 정의 확인은 `true`만 받는다. 집계 시작일과 종료일은 계획의 해당 기간과 정확히 같아야 하고 기간이 모두 끝난 뒤에 기록할 수 있다. 지원 통화는 KRW, USD, JPY, EUR이며 계획과 기록의 통화가 같아야 한다. 금액은 통화의 최소 단위 정수로 저장해 소수 계산의 오차를 줄인다.

| 사업 지표 | 계산과 결측 처리 |
| --- | --- |
| 세션 전환율 | 전환이 한 번 이상 발생한 세션 / 전체 세션. 주문 수를 분자로 사용하지 않는다. |
| 세션당 매출 | 기간 매출 / 전체 세션. 세션이 0이거나 필요한 값이 없으면 계산하지 않는다. |
| 기간 매출 | 입력한 집계 금액. 네 구간의 출처 조건이 충족돼야 전후 차이를 계산한다. |

측정하지 않은 값은 `null`로 남기며 실제로 0이라고 확인한 경우에만 0을 입력한다. 전환 세션이 전체 세션보다 많거나 전체 세션 없이 전환 세션만 입력하는 경우를 거부한다. 세션이 0인데 양수 매출이 입력된 경우도 거부한다. 세션, 전환 세션, 주문은 각각 최대 10억, 매출은 최소 통화 단위 기준 최대 1조로 제한한다.

검색 비율과 사업 지표에는 다음 차이를 기술통계로 보여준다.

```text
(개선 대상의 변경 후 − 변경 전) − (비교 대상의 변경 후 − 변경 전)
```

비교 대상의 변화를 빼는 계산은 **인과효과나 통계적 유의성의 증명으로 표시하지 않는다.** 두 대상의 사전 추세와 질문 대표성, 광고, 가격, 재고, 계절성, 모델 업데이트 등을 함께 확인해야 한다. 검색에서 브랜드를 본 뒤 직접 방문한 구매처럼 유입 출처에 잡히지 않는 경우도 남는다. 현재 기능은 AI 검색이 매출을 늘렸는지 판단하기 위한 근거를 정리하며, 매출 증가 자체를 보증하지 않는다.

## 기록 보존, 접근 통제와 무료 운영

계획과 기록은 로그인한 소유자의 워크스페이스에서만 조회하고 변경할 수 있다. 서버에서 소유권을 확인하고 변경 요청에는 동일 출처 검사를 적용한다. 샘플 워크스페이스에는 실제 검색 검증 계획을 만들 수 없다. 요청 ID를 사용한 재시도와 데이터베이스의 고유 인덱스로 같은 관측 칸이 중복 저장되는 것을 막는다.

저장한 계획과 관측 원문은 덮어쓰지 않는다. 오류가 있으면 원본, 제외 시각과 사유를 보존한 채 집계에서 제외하고 새 기록을 추가한다. 이미 제외한 기록의 사유도 바꿀 수 없다. SHA-256 해시는 저장 내용의 변경 여부를 확인하는 데 쓰이며 입력한 사실의 진위를 증명하지 않는다. 제외된 기록도 저장 한도와 백업에 포함된다.

| 워크스페이스별 한도 | 최대 행 수 | 백업 크기 추정 한도 |
| --- | ---: | ---: |
| 검증 계획 | 50 | 512 KiB |
| 검색 관측 | 5,000 | 3 MiB |
| 사업 집계 | 1,000 | 1 MiB |

행 수와 JSON 전송 크기 추정치를 같은 저장 조건에서 검사한다. 검색 관측과 사업 집계는 나중에 제외 사유를 보관할 공간도 미리 확보한다. 행 수보다 크기 한도에 먼저 도달할 수 있다. 한도에 도달하면 새 저장을 거부하며 기존 자료를 임의 삭제하지 않는다.

새 기능의 저장, 비교, 내보내기는 외부 AI 요청과 GA4 재인증 또는 추가 가져오기를 실행하지 않는다. Gemini 무료 수집 정책과 기존 호출 한도를 유지하고 유료 제공자로 전환하거나 폴백하지 않는다. 이번 구현은 기존 매시간 클라우드 수집기를 새로 만들거나 복제하지 않는다.

기존 7일 운영 검증 일정 `a3229692-68a4-4f96-9fce-6c4150602f6d`는 고정 질문 하나와 무료 Gemini를 사용하며 매일 19:20 Asia/Seoul, 종료 시각은 2026-10-25 19:15 KST인 설정을 유지한다. 이 릴리스 기능은 해당 일정을 수정하거나 즉시 수집을 실행하는 경로를 추가하지 않는다. 운영 검증의 성공과 실패 관측은 별도의 [운영 검증 기록](../../docs/free-launch-and-soak.md)을 따른다. 운영 안정성과 마케팅 효과는 별도로 판정한다.

## 백업 호환성과 검증 상태

새 백업은 V3이며 검증 계획, 검색 관측, 사업 집계 테이블을 포함한 18개 테이블과 5개 고정 마이그레이션을 사용한다. 추가 마이그레이션은 `0004_medical_master_chief.sql`이다. 기존 일정의 실행 설정을 변경하는 마이그레이션은 아니다.

V1과 V2는 각각 원래의 테이블 목록, 마이그레이션 체크섬과 원본 digest를 그대로 검증한다. V1은 원래 14개 테이블과 3개 마이그레이션, V2는 15개 테이블과 4개 마이그레이션을 사용한다. 복원할 때만 새 격리 복사본에 없는 테이블을 빈 상태로 추가한다. 과거 백업에 새로운 관측 데이터가 있었다고 만들어 넣지 않는다.

V3는 전체 백업 digest뿐 아니라 검증 계획과 관측의 개별 digest, 부모 관계, 질문 연결, 중복 활성 관측, 시간과 집계 조건도 검사한다. 원래 인용과 후속 검색의 구분, 제외 사유를 보존한다. 전체 백업 한도는 8 MiB와 20,000행이다.

복구는 `scripts/verify-backup.mjs`를 통한 새 격리 로컬 D1에서만 수행한다. 기존 데이터가 있는 대상은 거부하고, 식별자를 재매핑하며, 모든 복원 일정을 비활성화한다. 진행 중인 수집은 중단된 상태로 바꾸고 OAuth 자격 증명과 호출 예약, 운영 heartbeat 등의 실행 상태를 복원하지 않는다. 운영 DB를 덮어쓰거나 외부 요청을 보내지 않는다. 무결성, 외래 키와 행 개수, 복원한 값의 일치를 확인하며 원문이나 자격 증명을 로그에 출력하지 않는다.

작성 시점에 확인된 검증 범위는 다음과 같다.

- 통합 자동 테스트 204개 통과, TypeScript 검사 통과.
- 인용 분모, 측정 불가와 실제 0, 중복과 합성 데이터 분리, 최신 실패 수집의 표시.
- 원본 인용과 후속 검색 구분, 같은 질문과 회차의 전후 쌍, 실패와 미관측 처리.
- 출처 ID 불일치, UTC 집계, 미완료 기간, 잘못된 시간대와 지원하지 않는 통화의 거부.
- 소유권 경계, 요청 재시도, 동시 중복 저장, 원본 보존과 사유가 있는 제외.
- V1/V2/V3 백업 호환, 관측 무결성과 격리 복구, 일정 비활성화와 외부 호출 차단.

로컬 브라우저 검증은 실제 API 키가 없고 모든 제공자 호출이 차단된 격리 복사본에서 진행했다. 브랜드 등록, 3단계 계획 저장, 검색 기록 4개, 원래 인용과 후속 검색 링크, 오류 기록 제외와 재입력, 사업 집계 4개, 비교 결과까지 확인했다. 가상 자료에서 검색 언급과 인용의 전후 차이 100%p, 비교 대상의 변화를 뺀 전환율 차이 2%p, 세션당 매출 차이 200원이 기대값과 일치했다. 이 수치는 실제 성과가 아니다. 잘못된 기록은 원본과 제외 이력이 남았다.

날짜 입력 후 다른 필드를 수정할 때 값이 초기화되는 문제를 수정했고 적용 시각 유지와 저장을 확인했다. 데스크톱과 390px, 320px 화면을 확인했으며 모바일 문서 가로 넘침은 없었다. 빈 자료는 측정 불가로 표시됐다. 검증 자료는 운영 DB에 저장하지 않았다.

배포 전 운영 백업 V2 36행을 새 격리 D1에 복원했다. 무결성 정상, 외래 키 오류 0, 복원 일정 1개 비활성화, 외부 호출 0이었다. 이 복원은 10월 25일 최종 운영 검증을 대신하지 않는다. 배포 후 결과는 상위 운영 문서에 기록한다. 실제 AI 검색 노출 증가, 매출 증가와 7일 운영 검증 완료는 아직 입증되지 않았다.
